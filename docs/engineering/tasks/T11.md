## Yêu cầu

1. **Interface**: `class LLMClient(Protocol): def generate(self, messages: list[ChatMessage], *, temperature: float = 0.0, seed: int = 42, max_tokens: int = 512) -> LLMResult`. `ChatMessage = {role: 'system'|'user'|'assistant', content: str}`. `LLMResult`: `text`, `model`, `prompt_tokens`, `completion_tokens`, `load_ms`, `generate_ms`, `total_ms` (lấy từ trường thời gian của Ollama, đổi ns → ms), `queue_wait_ms`.
2. **`OllamaClient`** (sync, `httpx.Client`): `POST {DUT_LLM_BASE_URL}/api/chat` với `stream: false`, `options: {temperature, seed, num_predict, num_ctx}` (`DUT_LLM_NUM_CTX`, mặc định 4096), `keep_alive` (`DUT_LLM_KEEP_ALIVE`, mặc định `"30m"`). Timeout tổng `DUT_LLM_TIMEOUT_S` (90).
3. **Hàng đợi/semaphore** (an toàn đa luồng vì endpoint FastAPI sync chạy trong threadpool): tối đa 1 request đang sinh; tối đa 3 request chờ; request thứ 5 đồng thời → `LLMBusy` ngay; request chờ quá `DUT_LLM_QUEUE_WAIT_S` (30) → `LLMBusy`. Một instance dùng chung toàn tiến trình (`get_llm_client()` có cache; test thay được qua dependency override).
4. **Lỗi**: kết nối thất bại/HTTP 5xx từ Ollama/model không tồn tại → `LLMUnavailable`; quá thời gian → `LLMTimeout`; phản hồi không đúng dạng → `LLMUnavailable`. Ba ngoại lệ có `status_code` và `code` theo hợp đồng; thêm handler chuyển thành response lỗi chuẩn `{error:{code,message,request_id}}` (thông báo tiếng Việt: "Trợ giảng đang bận, vui lòng thử lại sau ít phút." / "Không kết nối được mô hình ngôn ngữ." / "Mô hình phản hồi quá lâu.") — đặt handler trong `app/rag/llm.py` với hàm `register_llm_errors(app)`; Tech Lead sẽ gọi trong `main.py` khi tích hợp (ghi trong báo cáo).
5. **Làm nóng**: `warm_up() -> LLMResult` gửi 1 prompt ngắn với `keep_alive`; CLI `uv run python -m app.rag.llm --warm` in thời gian nạp (`load_ms`) và tổng. CLI `--ping` kiểm `GET /api/version` + mô hình có trong `/api/tags`.
6. **`FakeLLMClient`** cho test các task sau: trả nội dung định sẵn hoặc theo hàm, có thể giả lập độ trễ và ném từng loại lỗi; ghi lại messages đã nhận.
7. Log mỗi lần gọi (model, token, các mốc ms, mã lỗi) bằng `logging`, **không** log nội dung prompt/câu trả lời.

## Test bắt buộc (không cần DB, không cần Ollama thật)

Dùng `httpx.MockTransport`:
- Thành công: parse đúng text, token, đổi ns → ms, gửi đúng `options`, `stream=false`, `keep_alive`.
- Ollama tắt (ConnectError) → `LLMUnavailable` 503; HTTP 500 / 404 model → 503; JSON sai dạng → 503; timeout → `LLMTimeout` 504.
- Đồng thời: với transport chậm (dùng `threading.Event`), 1 đang chạy + 3 chờ được chấp nhận, request thứ 5 → `LLMBusy` ngay; request chờ quá ngưỡng (đặt ngưỡng nhỏ trong test) → `LLMBusy`; sau khi request đầu xong, request chờ được chạy theo thứ tự.
- Handler lỗi trả đúng mã HTTP và `error.code` qua một app FastAPI nhỏ trong test.
- `FakeLLMClient` thỏa `LLMClient` (mypy) và ghi lại messages.

Kiểm tra thật (Tech Lead chạy ngoài sandbox, ghi kết quả): `--ping`, `--warm` với Ollama đang chạy.
