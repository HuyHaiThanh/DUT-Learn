## Yêu cầu

1. **Storage** (`app/materials/storage.py`): `Protocol Storage { put(key, bytes) ; open(key) -> BinaryIO ; exists(key) }` + `LocalStorage(root=DUT_DATA_DIR)`. Key do server sinh: `materials/<material_id>/<version_id>.<pdf|txt|md>` — **không** dùng tên tệp người dùng trong đường dẫn; chống path traversal; ghi tệp tạm rồi đổi tên (atomic).
2. **Kiểm tra tệp** (trước khi tạo bản ghi): ≤ 50 MB (đọc theo khối, dừng khi vượt → 413 `file_too_large`); PDF: 5 byte đầu `%PDF-` (+ mở được bằng PyMuPDF thì để T09 — ở đây chỉ kiểm magic); TXT/MD: giải mã UTF-8 nghiêm ngặt, ≤ 50 MB; loại khác → 415 `unsupported_media_type`. Tính SHA-256.
3. **API**
   - `POST /api/classes/{class_id}/materials` (multipart: `file`, `title` 1–200, `lesson_id?` thuộc cùng lớp, `visibility` mặc định `students`, `source_note?`, `license_note?`) — giảng viên lớp. Tạo `materials` (`kind` = `pdf|text`) + `material_versions` v1 `uploaded`, `created_by`, `original_filename`, `size_bytes`, `checksum_sha256`; gọi `enqueue_ingest(version_id)` **sau commit**. 201 `{material, version}`.
   - `POST /api/materials/{material_id}/versions` (multipart `file`) — giảng viên lớp chứa material; `version_no` = max + 1 với khóa hàng `SELECT … FOR UPDATE` trên material (hai upload đồng thời không trùng số); cùng `kind` với material (khác → 422).
   - `GET /api/classes/{class_id}/materials` — thành viên. Giảng viên: mọi material kèm danh sách version (id, version_no, status, created_at, size_bytes, error). Sinh viên: **chỉ** material `visibility=students` có `active_version_id` trỏ tới version `published`, chỉ trả `{id, title, lesson_id, kind, active_version_id, page_count, source_note, license_note}` (ghi nguồn/giấy phép là thông tin công khai); không trả version khác, trạng thái hay lỗi xử lý.
   - `GET /api/material-versions/{version_id}` — chỉ giảng viên lớp: trạng thái + `quality_report` + `error`.
   - `GET /api/material-versions/{version_id}/file` — giảng viên lớp: mọi version; sinh viên: chỉ khi version là `active_version_id`, status `published`, `visibility=students`, lớp `open` và SV là thành viên. Trả nội dung với `Content-Type` đúng, `Cache-Control: private, no-store`, `X-Content-Type-Options: nosniff`, `Content-Disposition: inline; filename*=` (tên an toàn). Không có quyền → 404.
   - Kiểm quyền qua hàm trung tâm trong `deps.py`; thêm hàm dùng chung `can_read_version(db, user, version) -> bool` trong `app/materials/policy.py` để T09/T10/T12 tái dùng (I1, I2).
4. **Hàng đợi ingest** (`app/ingest/queue.py`): `enqueue_ingest(version_id: UUID) -> None` là điểm nối cho T09; ở T08 chỉ ghi log + để trống (T09 thay thân hàm). Test có thể monkeypatch.
5. `audit_events`: `material.create`, `material_version.create`.

## Test bắt buộc (pytest, DB thật, thư mục dữ liệu tạm qua `tmp_path`)

- Upload PDF/TXT/MD hợp lệ → tệp nằm dưới key do server sinh, checksum đúng, version 1 `uploaded`, `enqueue_ingest` được gọi đúng một lần sau commit.
- Tệp giả PDF (sai magic), UTF-8 hỏng, quá 50 MB (giả lập giới hạn nhỏ qua cấu hình), tên tệp `../../x.pdf` → không tạo bản ghi, không ghi tệp ngoài thư mục.
- Ma trận quyền cho mọi endpoint: GV lớp / SV lớp / GV lớp khác / SV lớp khác / admin không thuộc lớp / chưa đăng nhập / thiếu CSRF.
- Sinh viên **không** đọc được: version `uploaded|ready|failed|superseded|revoked`, version không phải active, material `visibility=lecturers`, lớp `closed` — tạo trạng thái bằng cách ghi DB trực tiếp trong test (công bố thật thuộc T10). Đọc được active published → 200 + header đúng.
- Hai lần thêm version tuần tự → version_no 2, 3; `lesson_id` thuộc lớp khác → 422/404.
